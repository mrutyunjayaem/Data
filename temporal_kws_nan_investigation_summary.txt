TEMPORAL KWS NaN INVESTIGATION Technical summary, test results, and
proposed remediation Status: Immediate root cause confirmed; remediation
proposed but NOT yet applied

1.  PROBLEM

During temporal keyword-spotting (KWS) stream processing, frame-level
feature NPZ files contained NaN values.

Initial inspection of two affected streams found:

-   dev_009:
    -   rms_db: 36,440 NaNs out of 121,985 frames (approximately
        29.87%).
    -   blank: 84 NaNs.
    -   entropy: 84 NaNs.
    -   log_delta: 1 NaN.
    -   First invalid RMS frame: 85,545; preceding frame 85,544 was
        valid.
-   dev_019:
    -   rms_db: 91,286 NaNs out of 122,530 frames (approximately 74.5%).
    -   blank: 73 NaNs.
    -   entropy: 73 NaNs.
    -   log_delta: 1 NaN.
    -   First invalid RMS frame: 31,244; preceding frame 31,243 was
        valid.

The RMS NaNs appeared as continuous tail regions. This pattern suggested
that a non-finite sample entered the waveform and then propagated
through the cumulative sum used for RMS calculation.

2.  RELEVANT PIPELINE LOGIC

The stream synthesis function loads speech and, for noisy conditions,
mixes it with a noise segment.

Simplified relevant logic:

    speech = load_audio(clip["path"])
    gap = torch.zeros(int(round(clip["gap"] * sample_rate)))
    x = torch.cat([gap, speech])

    if clip["snr"] is not None:
        noise = load_noise(clip["noise"])
        ...
        speech_power = speech.pow(2).mean().clamp_min(1e-10)
        noise_power = noise.pow(2).mean().clamp_min(1e-10)
        scale = torch.sqrt(
            speech_power / (noise_power * 10 ** (clip["snr"] / 10))
        )
        x = x + scale * noise

The RMS calculation uses a cumulative sum of squared waveform samples:

    sq = np.r_[0.0, np.cumsum(wav.numpy().astype(np.float64) ** 2)]
    end = np.minimum(start + window_size, wav.numel())
    rms_db = 10 * np.log10(
        (sq[end] - sq[start]) / np.maximum(end - start, 1) + 1e-10
    )

A NaN in the waveform can contaminate the cumulative sum from that point
onward, producing the observed continuous tail of invalid RMS values.

8.  CONFIRMED ROOT CAUSE

The immediate cause of the NaNs is confirmed:

-   Three WAV entries in the source dataset archive are empty (44-byte
    WAV headers with zero audio frames).
-   The two empty clips used in dev_009 and dev_019 are loaded as
    zero-length tensors.
-   For an empty tensor, speech.pow(2).mean() evaluates to NaN because
    the mean of an empty tensor is undefined.
-   clamp_min(1e-10) does not turn NaN into a finite value.
-   The resulting mixing scale becomes NaN.
-   Mixing then introduces non-finite values into the synthesized
    waveform.
-   The cumulative squared-waveform sum used for RMS calculation
    propagates the invalid values, explaining the continuous NaN tails
    in rms_db.

This is a source-data integrity issue. The tests do not indicate that
the model itself generated these NaNs.

9.  PROPOSED SOLUTION

A practical solution is to remove the three known empty WAV files from
the extracted dataset AND ensure that the metadata used to construct
streams no longer includes their corresponding clip records.

Important: Deleting only the WAV files is not sufficient. If metadata
still references those files, later processing may fail with
missing-file errors.

Recommended safe procedure:

A. Back up the relevant metadata and record the three IDs.

B. Identify the source metadata file(s) consumed by the dataset
preparation function (for example, the metadata loaded by
prepare_snips()). Inspect how positive and negative clip records are
represented and where their audio paths are assigned.

C. Filter out records whose audio file is missing, zero-length, or has
zero decoded audio frames. At minimum, exclude the three confirmed IDs.
Prefer a general validation check so future empty files are caught
automatically.

D. Remove the three empty WAV files from the extracted audio directory
only after confirming the metadata filter is in place. The original TAR
archive does not need to be modified.

E. Rebuild the prepared clip metadata and temporal stream metadata.
Because stream construction depends on the available clip records, the
existing streams may still reference the invalid clips and must not be
reused unchanged.

F. Regenerate the affected frame outputs after the corrected streams
have been created. Confirm whether the run fingerprint changes and
ensure the new output directory/metadata is used, rather than
accidentally mixing old and new outputs.

G. Validate the regenerated results: - Check that every selected speech
WAV exists and has at least one decoded frame. - Check that synthesized
waveforms contain only finite samples. - Check that rms_db, blank,
entropy, log_delta, and all score arrays contain no NaNs or
infinities. - Specifically recheck dev_009 and dev_019, and scan all
generated stream NPZ files.

10. SUGGESTED VALIDATION GUARD

Add a guard in the data preparation stage or immediately after loading
speech audio. For example:

    speech = load_audio(clip["path"])

    if speech.numel() == 0:
        raise ValueError(
            f"Empty speech audio for clip {clip['id']}: {clip['path']}"
        )

    if not torch.isfinite(speech).all():
        raise ValueError(
            f"Non-finite speech audio for clip {clip['id']}: {clip['path']}"
        )

Also validate the noise tensor before mixing:

    if noise.numel() == 0 or not torch.isfinite(noise).all():
        raise ValueError(f"Invalid noise audio: {clip['noise']}")

A more robust approach is to filter invalid audio records before stream
construction, while retaining explicit runtime validation so invalid
files cannot silently enter the pipeline again.

Do not use NaN-to-zero replacement as the primary repair. It would
conceal the empty source audio and could change the temporal stream
evaluation.

11. CURRENT STATUS AND LIMITATIONS

Confirmed: - The two affected streams contain non-finite waveform
samples. - The two problematic speech WAV files are empty. - The
associated noise WAV files are valid. - There are exactly three 44-byte
WAV files in the extracted directory scan. - All three are also 44-byte
entries in the original TAR archive. - The immediate NaN mechanism is
explained by the empty speech tensors and subsequent noise-mixing
calculation.

Not yet done: - The source metadata format and exact metadata file(s)
have not yet been inspected. - No metadata records have been filtered or
edited. - No WAV files have been deleted. - No stream metadata has been
rebuilt. - No frame outputs have been regenerated. - No post-fix
validation has been performed.

Therefore, the proposed remediation is not yet applied or verified.
